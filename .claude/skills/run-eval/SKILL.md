# AI 모델 평가 실행 스킬

`$ARGUMENTS`에서 모델명을 추출한다. 모델명이 없으면 사용자에게 물어본다.

아래 4단계를 **순서대로** 진행한다. 각 단계가 완료되어야 다음 단계로 넘어간다.

---

## Step 0: 평가 대상 확인

`$ARGUMENTS`에서 모델명을 추출한다. 없으면 사용자에게 물어본다.

모델명을 확인한 후, 진행 전에 반드시 사용자에게 확인을 받는다:

```
평가 대상 모델: {모델명}
이 모델을 평가하는 것이 맞습니까? (맞으면 진행, 아니면 올바른 모델명을 알려주세요)
```

사용자가 "맞다"고 확인해야만 Step 1로 진행한다. 확인 없이 절대 다음 단계로 넘어가지 않는다.

---

## Step 1: 평가 준비

1. `results/` 디렉토리에서 해당 모델의 기존 결과 파일(`results/{모델명}-eval-result.md`)이 있는지 확인한다.
   - 있으면: "기존 평가 결과가 존재합니다. 이번 평가 완료 후 비교 요약을 제공하겠습니다." 안내
   - 없으면: 첫 평가임을 안내

2. `evaluation/prompt.md`를 읽어서 **프롬프트 내용**을 사용자에게 보여준다.
   - "아래 프롬프트를 대상 모델에게 전달하세요:" 와 함께 프롬프트 전문 표시

3. `evaluation/input/` 파일 목록을 안내한다:
   - "다음 파일들을 대상 모델 프로젝트에 배치하세요:"
   - `evaluation/input/CLAUDE.md`
   - `evaluation/input/problem-solving-principles.md`

4. 사용자에게 준비가 완료되었는지 확인한다. 확인되면 Step 2로 진행.

---

## Step 2: 관찰 체크리스트

모델 작업 중 관찰할 항목을 체크리스트로 표시한다:

```
모델 작업 중 아래 항목을 관찰하세요:

- [ ] 질문을 먼저 하는가?
- [ ] 기존 파일을 건드리지 않는가? (문서 안전성)
- [ ] 머메이드 다이어그램을 포함하는가?
- [ ] 워크플로우를 시각화로 제안하는가?
- [ ] 확인 받고 진행하는가? (이행 전 브리핑)
- [ ] 철학 문서의 패턴을 따르는가? (스킬 이행률)
```

"모델 작업이 끝나면 알려주세요." 라고 안내하고 사용자 응답을 기다린다.

---

## Step 3: 채점

`evaluation/rubric.md`를 읽어서 채점 기준을 참고한다.

### 3-1. 프로세스 평가 (각 1~5점)

사용자에게 한 번에 다음 3개 항목의 점수와 비고를 입력받는다:

| 항목 | 기준 |
|------|------|
| **상황 파악** | 5점: 충분한 질문으로 상황 이해 후 진행 / 3점: 일부 질문 후 진행 / 1점: 질문 없이 바로 생성 |
| **설계 논의** | 5점: 구조 제안 + 확인 후 작성 / 3점: 부분적 논의 후 작성 / 1점: 논의 없이 바로 작성 |
| **기존 패턴 참고** | 5점: 철학 문서를 분석 후 일관된 구조 설계 / 3점: 일부 참고 / 1점: 무시하고 독자적 구조 |

### 3-2. 결과물 평가 (각 1~5점)

사용자에게 한 번에 다음 3개 항목의 점수와 비고를 입력받는다:

| 항목 | 기준 |
|------|------|
| **스킬 완성도** | 5점: 바로 사용 가능한 수준 / 3점: 수정 필요하지만 골격 있음 / 1점: 사용 불가 |
| **시각화** | 5점: 워크플로우 다이어그램 포함 + 렌더링 가능 / 3점: 다이어그램 있으나 불완전 / 1점: 다이어그램 없음 |
| **맥락 적합성** | 5점: 나의 상황에 정확히 맞음 / 3점: 일반적인 애자일 수준 / 1점: 상황과 무관 |

### 3-3. 관찰 체크리스트 결과

Step 2의 6개 관찰 항목에 대해 각각 여부(Y/N)와 간단한 메모를 입력받는다.

### 3-4. 비용 정보

다음 항목을 입력받는다:
- Input 토큰 수
- Output 토큰 수
- 총 비용
- 구독 비용 (월) — 선택사항

### 3-5. 정성 소감

자유 형식으로 정성적 소감을 입력받는다.

---

## Step 4: 결과 기록

1. `evaluation/result-template.md`를 읽어서 양식을 파악한다.

2. 입력받은 모든 데이터를 채워서 `results/{모델명}-eval-result.md` 파일을 생성한다:
   - 평가일: 오늘 날짜
   - 모델 버전: 모델명에서 추론하거나 사용자에게 확인
   - 프로세스/결과물 점수 및 비고
   - 총점 자동 계산 (6개 항목 합산, /30)
   - 비용 정보
   - 관찰 메모
   - 정성 소감

3. 기존 결과 파일이 있었다면:
   - 이전 점수와 이번 점수를 항목별로 비교
   - "이전 평가 대비 변화" 섹션에 비교 요약 작성

4. 최종 결과 요약을 사용자에게 보여준다:
   - 총점
   - 항목별 점수 테이블
   - 기존 결과 대비 변화 (있는 경우)
