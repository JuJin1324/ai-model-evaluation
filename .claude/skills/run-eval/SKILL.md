# AI 모델 평가 실행 스킬

`$ARGUMENTS`에서 모델명을 추출한다. 모델명이 없으면 사용자에게 물어본다.

아래 5단계를 **순서대로** 진행한다. 각 단계가 완료되어야 다음 단계로 넘어간다.

---

## Step 0: 평가 대상 확인

`$ARGUMENTS`에서 모델명을 추출한다. 없으면 사용자에게 물어본다.

모델명은 **에이전트 + 모델 버전**이 포함된 상세 이름이어야 한다.
- 좋은 예: "Claude Code Opus 4.6", "Codex CLI o4-mini", "Gemini CLI 2.5 Pro"
- 나쁜 예: "claude", "codex", "gemini"

모델명을 확인한 후, 진행 전에 반드시 사용자에게 확인을 받는다:

```
평가 대상 모델: {모델명}
이 모델을 평가하는 것이 맞습니까? (맞으면 진행, 아니면 올바른 모델명을 알려주세요)
```

사용자가 "맞다"고 확인해야만 Step 1로 진행한다. 확인 없이 절대 다음 단계로 넘어가지 않는다.

---

## Step 1: 평가 셋업

1. `results/` 디렉토리에서 해당 모델의 기존 결과 파일(`results/{모델명}-eval-result.md`)이 있는지 확인한다.
   - 있으면: "기존 평가 결과가 존재합니다. 이번 평가 완료 후 비교 요약을 제공하겠습니다." 안내
   - 없으면: 첫 평가임을 안내

2. 모델의 출력물 디렉토리를 안내한다:
   - `evaluation/output/{모델명}/` 디렉토리가 평가 대상 모델이 스킬을 생성할 위치임을 안내

3. **평가 문서 파일**을 자동 생성한다 (`evaluation/output/{모델명}/` 아래):
   - `evaluation/templates/eval-notes-template.md`를 참고하여 `eval-notes.md` 생성
   - `evaluation/templates/eval-scoring-template.md`를 참고하여 `eval-scoring.md` 생성
   - 템플릿의 `{모델명}`, `{오늘 날짜}`를 실제 값으로 치환

4. 사용자에게 파일 생성을 알리고, 평가 셋업을 안내한다:

```
📋 평가 셋업 안내

평가 문서가 생성되었습니다:
- 관찰 노트: evaluation/output/{모델명}/eval-notes.md
- 채점 문서: evaluation/output/{모델명}/eval-scoring.md

1. 별도 세션/터미널에서 대상 모델을 엽니다
2. 새 프로젝트 디렉토리에 아래 파일을 배치합니다:
   - evaluation/input/philosophy.md
3. .claude/skills/ 기존 스킬이 없는 상태인지 확인합니다
```

사용자가 셋업 완료를 확인하면 Step 2로 진행한다.

---

## Step 2: 평가 실행

사용자에게 평가 실행을 안내한다:

```
📋 평가 실행
```

대상 모델에게 아래 프롬프트를 전달하고 작업을 시작하세요:

```
이 프로젝트의 philosophy.md를 읽고,
이 철학을 기반으로 2W1H 서사부터 스프린트 실행까지 가능한
애자일 프로세스 스킬을 설계하고 만들어줘.
```

평가 핵심: 모델이 philosophy.md를 읽고 스킬을 설계/생성하는 전체 과정을 관찰합니다.
- 바로 만드는가, 질문을 먼저 하는가?
- 기존 파일을 수정하는가, 새 파일만 만드는가?
- 확인을 받고 진행하는가?

모델 작업이 끝나면 알려주세요.

사용자가 모델 작업 완료를 알리면 Step 3으로 진행한다.

---

## Step 3: 채점

1. 평가로 생성된 스킬을 보존한다:
   - 대상 모델이 `.claude/skills/` 아래에 생성한 스킬들을 `evaluation/output/{모델명}/skills/`로 이동한다.
   - `mv` 명령어로 스킬 디렉토리/파일을 이동 (run-eval 스킬 자체는 제외).

2. `evaluation/rubric.md`를 읽어서 채점 기준을 사용자에게 안내한다.

3. `evaluation/output/{모델명}/eval-notes.md`를 읽어서 관찰 기록을 참고한다.

4. 사용자에게 채점 문서 작성을 안내한다:

```
📋 채점 안내

채점 문서를 작성해주세요: evaluation/output/{모델명}/eval-scoring.md
- 8개 항목 점수(각 1~5)와 비고
- 비용 정보 (선택사항)

작성이 끝나면 알려주세요.
```

5. 사용자가 채점 완료를 알리면 `eval-scoring.md`를 읽어서 Step 4로 진행한다.

---

## Step 4: 결과 기록

1. `evaluation/result-template.md`를 읽어서 양식을 파악한다.

2. 입력받은 모든 데이터를 채워서 `results/{모델명}-eval-result.md` 파일을 생성한다:
   - 평가일: 오늘 날짜
   - 모델 버전: 모델명에서 추론하거나 사용자에게 확인
   - 프로세스 점수 소계 + 결과물 점수 소계 + 총점
   - 비용 정보 (없으면 "미측정" 표시)
   - 관찰 메모
   - 정성 소감

3. 기존 결과 파일이 있었다면:
   - 이전 점수와 이번 점수를 항목별로 비교
   - "이전 평가 대비 변화" 섹션에 비교 요약 작성

4. 최종 결과 요약을 사용자에게 보여준다:
   - 총점 (프로세스 /30 + 결과물 /50 = /80)
   - 항목별 점수 테이블
   - 기존 결과 대비 변화 (있는 경우)
