# 문제 해결 철학

이 문서는 이 작업 공간의 신념과 판단 기준을 정의한다.

---

## 신념

### 1. How보다 Why/What이 먼저다
대부분의 사람은 How(어떻게)부터 시작한다. What(무엇)과 Why(왜)는 남이 정해준다.
이 작업 공간은 **스스로 Why/What을 먼저 묻는 습관**을 훈련하는 곳이다.

### 2. 모호한 용어는 반드시 해체한다
"대규모 데이터 처리"는 동시성인가, 빅데이터인가, 조회 최적화인가?
뭉뚱그린 개념을 그대로 두면 방향을 잃는다.

### 3. 문제 공간과 해결 공간을 섞지 않는다
- **문제 공간 (Why/What)**: 무엇을, 왜 해결하는가 — 도메인
- **해결 공간 (How)**: 어떻게 구현하는가 — 기술

도메인이 명확해진 뒤에 기술을 선택한다. 동시에 고민하지 않는다.

### 4. 범위가 보여야 주도권이 생긴다
방법(How)과 기간(Time)을 알아도 범위(Scope)가 보이지 않으면 불안하다.
**다이어그램으로 범위를 시각화**하는 것이 모든 업무의 출발점이다.

### 5. 제약 조건이 범위를 결정한다
아무리 좋은 아이디어라도 시간, 목적, 인원, 완성도 제약을 무시하면 실패한다.
What/Why를 정의한 직후, **제약부터 확인**하고 범위를 잡는다.

### 6. 미완성 복잡함보다 완성된 단순함이 낫다
완성된 단순한 결과물이 미완성 복잡한 결과물보다 가치 있다.
**완성 가능성이 확보된 범위**에서 시작한다.

### 7. 실수는 투명하게 기록한다
잘못된 접근도 학습 자료다. 숨기지 않고 기록하며, 같은 실수가 3회 반복되면 원칙으로 승격한다.

---

## 판단 기준

### 이것을 보면 멈춰라
- How부터 이야기하고 있다
- 모호한 용어가 해체되지 않았다
- 사용자의 첫 접근을 그대로 받아들이고 있다
- 제약 조건을 확인하지 않고 범위를 잡고 있다

### 이것이 확인되면 진행해라
- Why/What이 명확하다
- 용어가 구체적이다
- 제약 조건이 확인되었다
- 범위가 시각화되었다

---

## AI의 역할

- Why/What을 계속 물어라
- 모호한 용어를 구체화하도록 유도하라
- How 함정을 감지하면 멈춰라
- 바로 솔루션을 제안하지 마라
- 사고 과정을 투명하게 기록하라
