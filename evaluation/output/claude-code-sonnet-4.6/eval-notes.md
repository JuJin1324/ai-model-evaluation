# Claude Code Sonnet 4.6 평가 관찰 노트

**평가일:** 2026-02-22

---

## 관찰 체크리스트

- [V] 질문을 먼저 하는가?
- [V] 기존 파일을 건드리지 않는가? (문서 안전성)
- [ ] 확인 받고 진행하는가? (이행 전 브리핑)
- [V] 철학 문서의 패턴을 따르는가? (스킬 이행률)

## 실시간 메모

질문이 기존 Opus 4.6과 정확히 같은 초반 질문을 선택지로 표현함. 그리고 난 평가를 위해서 같은 대답으로 선택하여 진행함.

클로드 코드 스킬스에서 적용할 수 있는 Argument 에 따라서 하나의 스킬에서 4개의 워크플로우를 나눈 부분은 나쁘지 않았음.

처음에 하나의 스킬만 제안해주는 것은 거의 대부분의 AI 모델들이 동일해보인다. 그리고 하나의 스킬만 제안해준 의도를 물어봤고, 명시적으로 말을 하지는 않았지만
먼저 하나로 된 것을 써보고 필요에 따라서 바꾸라는 MVP 의 결과 비슷한 답은 좋았다. 다만 Codex 처럼 애자일을 통해서 MVP 라는 단어를 명시적으로 주는 추론력에는
조금 못미친 것이 아닌가 하는 생각은 들었다.

일부러 처음에 만들어준 스킬에 유연함이 부족하다는 딴지를 걸어서 스킬을 나누도록 요청하였음. 거기서 기존에 참신하게 제안되었던 Argument 사용이 그대로 유지되었음.
이는 꽤나 유용하다고 생각됨. 오히려 Argument 가 스킬을 나누는 것 보다도 스킬을 유연하게 해줄거라는 생각이 들었음.

SKILL.md 안에 각각의 흐름 mermaid 다이어그램이 제공되므로써 사용자가 스킬을 읽고 이 스킬의 용도가 뭔지 파악하기에도 매우 좋은 시각화를 제공하였음.

스킬에 다른 스킬에 대한 결합도 방지를 목적으로 SKILL.md 에 다른 스킬명을 적는게 아니라 참조할 파일명을 적음으로써 결합도를 낮추는 작업을 했다. 이는 매우 좋은
설계가 되었음.

근데 이번에 Sonnet 4.6 을 썼을 때의 느낌은 초반에 필요한 정보를 주로 수집한 후에 추가적으로 질문을 하지는 않았다. 약간 모호하다고 생각하는 부분만 사용자에게 질문 후
모호하지 않다고 판단되는 부분은 본인 스스로 만드는건가 하는 느낌이 들었다. 왜냐면 스킬의 결과물이 꽤나 좋았다. 단순히 정보가 부족하기 때문에 어쩔 수 없이 진행한 추론이란
느낌이 들지 않고 사용자가 생각치 못한 부분을 보조해주는 추론이란 느낌을 받았음.
