# 스프린트 실행 스킬

sprint-plan에서 생성된 백로그를 읽어 **태스크를 순서대로 실행**한다.
각 태스크의 시작/완료를 추적하고, 차단 상황 발생 시 대응한다.

`$ARGUMENTS`에서 프로젝트명을 추출한다. 없으면 사용자에게 물어본다.

---

## 핵심 원칙

- **백로그 순서를 따른다** — 의존성이 반영된 순서를 임의로 바꾸지 않는다
- **한 번에 하나씩** — 현재 태스크 완료 후 다음으로 넘어간다
- **차단되면 기록하고 우회한다** — 막힌 채로 멈추지 않는다
- **실수는 투명하게 기록한다** — 잘못된 접근도 백로그에 남긴다
- **각 태스크 시작/완료 시 상태를 업데이트한다**

---

## Step 0: 백로그 확인

1. 최신 스프린트 백로그를 찾는다:
   - `docs/sprint/{프로젝트명}-sprint-*.md` 에서 가장 높은 번호의 파일
   - 없으면: "스프린트 백로그가 없습니다. `/sprint-plan {프로젝트명}`을 먼저 실행하세요." 안내 후 종료

2. 백로그를 읽어서 현재 상태를 파악한다:
   - 총 태스크 수
   - 완료된 태스크 (✅)
   - 진행 중인 태스크 (🔄)
   - 차단된 태스크 (🚫)
   - 대기 중인 태스크 (⬜)

3. 현재 상태를 사용자에게 보여준다:

```
📋 스프린트 현황

프로젝트: {프로젝트명}
백로그: docs/sprint/{프로젝트명}-sprint-{번호}.md

진행률: {완료}/{전체} ({퍼센트}%)
  ✅ 완료: {N}개
  🔄 진행 중: {N}개
  🚫 차단: {N}개
  ⬜ 대기: {N}개

다음 실행 태스크: #{번호} {태스크명}
시작할까요?
```

---

## Step 1: 태스크 실행 루프

다음 실행 가능한 태스크를 찾아 실행한다. 아래 과정을 태스크마다 반복한다.

### 1-1. 태스크 시작

실행할 태스크를 안내하고 백로그 상태를 업데이트한다:

1. 백로그 파일에서 해당 태스크의 상태를 `🔄 진행 중`으로 변경
2. 사용자에게 태스크를 안내:

```
▶️ 태스크 #{번호} 시작: {태스크명}

MVP 항목: {소속 MVP 항목}
의존성: {의존 태스크 또는 "없음"}

무엇부터 할까요?
```

### 1-2. 태스크 작업

사용자와 함께 태스크를 수행한다:
- 필요한 파일을 읽고, 코드를 작성하고, 명령을 실행한다
- 작업 중 판단이 필요하면 사용자에게 확인한다
- 예상치 못한 문제가 발생하면 기록한다

### 1-3. 태스크 완료 또는 차단

**완료 시:**
1. 사용자에게 완료를 확인한다: "태스크 #{번호}가 완료되었나요?"
2. 확인되면 백로그 파일에서 상태를 `✅ 완료`로 변경
3. 진행률을 업데이트하여 보여준다

**차단 시:**
1. 차단 사유를 기록한다
2. 백로그 파일에서 상태를 `🚫 차단`으로 변경하고 사유를 추가
3. 다음 실행 가능한 태스크(의존성 충족된 것)가 있으면 제안:

```
🚫 태스크 #{번호} 차단

사유: {차단 사유}

다음 실행 가능한 태스크:
  #{번호} {태스크명} — 의존성 충족됨

이 태스크로 넘어갈까요, 아니면 차단을 해결할까요?
```

### 1-4. 다음 태스크 전환

현재 태스크가 완료/차단되면:
1. 다음 실행 가능한 태스크(의존성 충족 + ⬜ 대기)를 찾는다
2. 있으면: Step 1-1로 돌아간다
3. 없으면: Step 2로 이동한다

---

## Step 2: 스프린트 종료 판단

모든 태스크가 완료되었거나, 더 이상 실행 가능한 태스크가 없을 때:

### 모든 태스크 완료

```
🎉 스프린트 완료

프로젝트: {프로젝트명}
완료: {전체}/{전체} (100%)

모든 MVP 태스크가 완료되었습니다.
`/sprint-retro {프로젝트명}`으로 회고를 진행할까요?
```

### 차단된 태스크 존재

```
⚠️ 스프린트 중단

프로젝트: {프로젝트명}
완료: {완료}/{전체} ({퍼센트}%)
차단: {차단 수}개

차단된 태스크:
  🚫 #{번호} {태스크명} — {사유}

선택지:
1. 차단 해결 시도
2. 차단된 태스크를 이후 범위로 이동하고 회고 진행
3. 스프린트 일시 중지 (나중에 /sprint-run으로 재개)
```

---

## 백로그 상태 관리 규칙

상태 변경 시 백로그 파일을 직접 수정한다:

| 상태 | 표시 | 전환 조건 |
|------|------|-----------|
| 대기 | ⬜ 대기 | 초기 상태 |
| 진행 중 | 🔄 진행 중 | 태스크 시작 시 |
| 완료 | ✅ 완료 | 사용자 확인 후 |
| 차단 | 🚫 차단({사유}) | 진행 불가 시 |

---

## 멈춰야 할 때

- 백로그에 없는 태스크를 추가하려 한다 → "백로그 범위 밖입니다. 필요하면 sprint-plan을 다시 실행하세요"
- 의존성이 충족되지 않은 태스크를 시작하려 한다 → "선행 태스크가 완료되지 않았습니다"
- MVP 범위를 넘어서는 작업을 하려 한다 → "MVP 범위를 지킵니다. 이후 범위는 다음 스프린트에서"

---

## 주의사항

- 백로그 파일 외의 서사/범위 문서는 수정하지 않는다
- 태스크 실행 중 생성한 파일은 프로젝트 구조에 맞게 배치한다
- 기존 프로젝트 파일을 수정할 때는 반드시 사용자에게 확인받는다
- 차단 사유는 구체적으로 기록한다 — "안 됨" (X), "외부 API 인증 키 미발급" (O)
- 스프린트 중간에 `/sprint-run`을 다시 실행하면 현재 상태부터 이어간다
