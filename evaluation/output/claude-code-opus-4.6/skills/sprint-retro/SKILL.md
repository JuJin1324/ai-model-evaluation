# 스프린트 회고 스킬

스프린트 실행 완료 후 **회고를 진행**하고, 다음 스프린트 여부를 판단한다.

`$ARGUMENTS`에서 프로젝트명을 추출한다. 없으면 사용자에게 물어본다.

---

## 핵심 원칙

- **실수는 투명하게 기록한다** — 잘못된 접근도 학습 자료
- **3회 반복된 실수는 원칙으로 승격한다**
- **완료된 것과 안 된 것을 명확히 구분한다**
- **다음 행동을 결정하고 끝낸다**

---

## Step 0: 스프린트 결과 수집

1. 관련 문서를 모두 읽는다:
   - `docs/narrative/{프로젝트명}-narrative.md` (서사 + 범위)
   - `docs/sprint/{프로젝트명}-sprint-{최신번호}.md` (백로그)

2. 없으면: "스프린트 백로그가 없습니다." 안내 후 종료

3. 스프린트 결과를 요약:

```
📋 스프린트 결과 요약

프로젝트: {프로젝트명}
스프린트: #{번호}

태스크 현황:
  ✅ 완료: {N}개 / {전체}개
  🚫 차단: {N}개
  ⬜ 미실행: {N}개

MVP 완성 여부: {완성 / 부분 완성 / 미완성}
```

---

## Step 1: 완료 조건 검증

서사 문서의 **완료 조건**과 실제 결과를 대조한다:

```
📋 완료 조건 검증

완료 조건: {서사에 정의된 완료 조건}

검증:
  ✅ {충족된 조건} — {근거}
  ❌ {미충족 조건} — {이유}

판정: {MVP 완성 / MVP 부분 완성}
```

사용자에게 확인: "이 판정이 맞나요?"

---

## Step 2: 회고 질문

사용자에게 3가지를 질문한다:

1. **잘된 것**: "이번 스프린트에서 잘 진행된 부분은 무엇인가요?"
2. **아쉬운 것**: "아쉬웠거나 다르게 했으면 좋았을 부분은?"
3. **배운 것**: "이번 스프린트에서 새로 알게 된 것이 있나요?"

---

## Step 3: 반복 실수 점검

### 3-1. 이전 회고 기록 확인

`docs/sprint/{프로젝트명}-sprint-*-retro.md` 파일들을 확인한다.

### 3-2. 반복 패턴 감지

이전 회고에서 같은 아쉬운 점이 반복되었는지 확인한다:
- 2회 반복: "이 패턴이 2회 반복되고 있습니다. 다음에도 반복되면 원칙으로 승격합니다." 경고
- 3회 이상 반복: "이 패턴이 3회 반복되었습니다. 원칙으로 승격을 제안합니다." 안내

원칙 승격 시 사용자에게 확인 후, 프로젝트의 원칙 문서에 추가할 수 있다.

---

## Step 4: 다음 단계 판단

### 4-1. 선택지 제시

```
📋 다음 단계

스프린트 #{번호} 회고가 완료되었습니다.

선택지:
1. 다음 스프린트 시작 — 이후 범위에서 다음 MVP를 잡습니다 (/scope-mvp)
2. 현재 범위 재계획 — 차단/미완성 태스크를 재계획합니다 (/sprint-plan)
3. 서사 재정의 — Why/What이 바뀌었으면 서사부터 다시 합니다 (/2w1h-narrative)
4. 프로젝트 완료 — 더 이상 스프린트가 필요 없습니다

어떻게 하시겠어요?
```

### 서사 문서 상태 업데이트

`docs/narrative/{프로젝트명}-narrative.md`의 상태를 업데이트:
- 다음 스프린트: "sprint-retro #{번호} 완료 — 다음 scope-mvp 대기"
- 프로젝트 완료: "프로젝트 완료"

### 최종 안내

```
📋 회고 기록 완료

파일: docs/sprint/{프로젝트명}-sprint-{번호}-retro.md

```

---

## 주의사항

- 회고 문서는 기존 스프린트 백로그와 별도 파일로 생성한다
- 서사 문서의 Why/What/Scope는 수정하지 않는다 — 상태만 업데이트
- 사용자가 솔직하게 답변할 수 있도록 판단하지 않는다
- 반복 실수 승격은 반드시 사용자 동의 후 진행한다
