# MVP 범위 정의 스킬

2w1h-narrative의 서사 문서를 입력으로 받아 **제약 조건 → 범위 시각화 → MVP 확정**을 수행한다.

`$ARGUMENTS`에서 프로젝트명을 추출한다. 없으면 사용자에게 물어본다.

---

## 핵심 원칙

- **제약이 범위를 결정한다** — 제약 없이 범위를 잡지 않는다
- **범위가 보여야 주도권이 생긴다** — 반드시 시각화한다
- **미완성 복잡함보다 완성된 단순함** — MVP는 완성 가능한 최소 범위
- **각 Step 완료 후 확인받는다**

---

## Step 0: 서사 문서 확인

1. `docs/narrative/{프로젝트명}-narrative.md` 파일을 찾는다.
   - 있으면: 읽어서 Why/What을 파악한다
   - 없으면: `docs/narrative/` 전체를 검색하여 유사한 파일을 찾는다
   - 그래도 없으면: "서사 문서가 없습니다. `/2w1h-narrative {프로젝트명}`을 먼저 실행하세요." 안내 후 종료

2. 서사 문서의 핵심을 요약하여 사용자에게 확인:

```
📋 서사 확인

Why: {배경/동기 한 줄 요약}
What: {문제 정의 한 줄}
완료 조건: {완료 조건}

이 서사를 기반으로 범위를 잡겠습니다. 맞나요?
```

---

## Step 1: 제약 조건 확인

사용자에게 **4가지 제약 조건**을 확인한다:

### 질문 목록

1. **시간**: "이 프로젝트/기능에 투입할 수 있는 시간은 얼마인가요? (예: 1주, 2스프린트, 이번 달 내)"
2. **인원**: "누가 참여하나요? (예: 나 혼자, 프론트 1 + 백엔드 1, AI와 나)"
3. **목적**: "이번 결과물의 목적은 무엇인가요? (예: PoC 검증, 실사용 배포, 내부 데모, 학습)"
4. **완성도**: "어느 수준까지 완성해야 하나요? (예: 동작하는 프로토타입, 프로덕션 레디, 문서까지 포함)"

### 제약 정리

```
📋 제약 조건 정리

시간: {시간 제약}
인원: {인원 제약}
목적: {목적}
완성도: {요구 완성도}

이 제약 조건이 맞나요?
```

---

## Step 2: 전체 범위 시각화

서사(Why/What)와 제약 조건을 기반으로 **전체 범위를 ASCII 다이어그램으로 시각화**한다.

### 2-1. 기능/작업 도출

서사 문서의 문제 정의와 완료 조건에서 필요한 기능/작업을 도출한다.
이때 사용자에게 빠진 것이 없는지 확인한다.

### 2-2. 범위 다이어그램

전체 범위를 ASCII로 시각화한다. 형식은 프로젝트 성격에 맞게 선택한다:

**기능 중심 프로젝트:**
```
┌─────────────────────────────────┐
│         {프로젝트명}              │
├─────────┬──────────┬────────────┤
│ 기능 A  │ 기능 B   │ 기능 C     │
│ - 세부1 │ - 세부1  │ - 세부1    │
│ - 세부2 │ - 세부2  │ - 세부2    │
└─────────┴──────────┴────────────┘
```

**흐름 중심 프로젝트:**
```
[입력] → [처리 A] → [처리 B] → [출력]
            │
            ├─ 세부 1
            └─ 세부 2
```

```
이것이 이 프로젝트의 전체 범위입니다.
빠진 기능이나 작업이 있나요?
```

---

## Step 3: MVP 범위 확정

### 3-1. MVP 기준 적용

제약 조건을 대입하여 MVP 범위를 제안한다:

판단 기준:
- 완료 조건을 최소한으로 충족하는가?
- 제약(시간/인원) 내에 **완성 가능한가**?
- 빠져도 핵심 가치가 유지되는 것은 무엇인가?

### 3-2. MVP vs 이후 범위 구분

```
📋 MVP 범위 제안

MVP (이번에 완성):
  ✅ {기능/작업 1} — 이유: {왜 MVP에 포함}
  ✅ {기능/작업 2} — 이유: {왜 MVP에 포함}

이후 (다음 스프린트):
  ⏳ {기능/작업 3} — 이유: {왜 이후로 미룸}
  ⏳ {기능/작업 4} — 이유: {왜 이후로 미룸}

이 MVP 범위로 진행할까요?
조정하고 싶은 항목이 있으면 알려주세요.
```

사용자가 조정을 요청하면 반영 후 다시 확인받는다.

---

## Step 4: MVP 범위 문서 작성

### 4-1. 서사 문서 업데이트

`docs/narrative/{프로젝트명}-narrative.md`에 Scope 섹션을 **추가**한다 (기존 내용 유지, 아래에 추가):

```markdown

---

## Scope — 범위

### 제약 조건
| 항목 | 내용 |
|------|------|
| 시간 | {시간} |
| 인원 | {인원} |
| 목적 | {목적} |
| 완성도 | {완성도} |

### 전체 범위
{ASCII 다이어그램}

### MVP 범위
| 항목 | 포함 여부 | 이유 |
|------|-----------|------|
| {기능1} | ✅ MVP | {이유} |
| {기능2} | ✅ MVP | {이유} |
| {기능3} | ⏳ 이후 | {이유} |

### 상태
**MVP 범위 확정** — sprint-plan 대기

---

## 다음 단계

이 범위를 기반으로 `/sprint-plan {프로젝트명}`을 실행하여 스프린트 백로그를 생성한다.
```

### 4-2. 최종 안내

```
📋 MVP 범위 확정 완료

파일 업데이트: docs/narrative/{프로젝트명}-narrative.md (Scope 섹션 추가)

MVP 범위: {MVP 항목 수}개 항목
이후 범위: {이후 항목 수}개 항목

다음 단계: /sprint-plan {프로젝트명}
→ MVP 범위를 스프린트 백로그로 분해합니다.
```

---

## 멈춰야 할 때

- 서사 문서 없이 범위부터 잡으려 한다 → "서사가 먼저입니다"
- 제약 조건 없이 MVP를 정하려 한다 → "제약이 범위를 결정합니다"
- MVP 범위가 제약 내에 완성 불가능해 보인다 → "완성 가능한 범위로 줄여야 합니다"
- 전체 범위를 MVP로 넣으려 한다 → "MVP는 최소 완성 범위입니다"

---

## 주의사항

- 서사 문서의 Why/What 섹션은 수정하지 않는다 — Scope 섹션만 추가
- How(기술 선택, 구현 방법)는 이 스킬의 범위가 아니다
- 다이어그램은 ASCII로 작성한다 — 터미널 환경에서 바로 확인 가능하도록
- 범위 조정은 사용자 확인 후에만 반영한다
