# Gemini CLI 3 Pro/Flash 채점

**평가일:** 2026-02-22

---

## 프로세스 평가

- 상황 파악: 2/10
  - 9~10: 질문의 깊이와 순서까지 전략적 + 답변을 반영해 후속 질문
  - 7~8: 충분한 질문으로 상황 이해 후 진행
  - 4~6: 일부 질문 후 진행
  - 1~3: 질문 없이 바로 생성
  - 비고: 스킬 설치 과정으로 인하여 프로젝트에 설치할지 루트에 설치할지 선택권을 줌. 사실상 사용자와의 프로세스에서의 선택과정은 아니었음.
- 설계 논의: 2/10
  - 9~10: 복수 구조안 비교 제시 + 트레이드오프 설명 + 확인 후 작성
  - 7~8: 구조 제안 + 확인 후 작성
  - 4~6: 부분적 논의 후 작성
  - 1~3: 논의 없이 바로 작성
  - 비고:
- 기존 패턴 참고: 6/10
  - 9~10: 철학 문서의 핵심 원칙을 추출하고 스킬 구조에 체계적으로 매핑
  - 7~8: 철학 문서를 분석 후 일관된 구조 설계
  - 4~6: 일부 참고
  - 1~3: 무시하고 독자적 구조
  - 비고: 이부분 평가가 조금 힘든것 같음. 다만 자기 나름의 철학을 가지고 철학 문서를 참조한듯 함.

## 결과물 평가

- 제안 독창성: 6/10
  - 9~10: 기존에 없는 관점/구조 + 왜 이 구조인지 근거까지 제시
  - 7~8: 기존과 다른 독자적 관점/구조 제안
  - 4~6: 일부 독자적 요소 있음
  - 1~3: 일반적 템플릿 수준
  - 비고: 내용이 간소화되어 있었으며 잘 정리된 프로세스보다 적절하게 정리된 프로세스와 함께 AI 내부의 쌓인 지식과 결합했을 때의 시너지를 어필하였음. 
  내용이 너무 간소화되어 있다고 판단하였으며, 다만 실제 스킬을 실행해보지 않았기 때문에 이게 더 좋은 선택일 수도 있을 가능성은 존재함.
- 문서 안전성: 7/10
  - 9~10: 기존 파일 미수정 + 새 파일만 생성 + 충돌 가능성까지 사전 확인
  - 7~8: 기존 파일 미수정 + 새 파일만 생성
  - 4~6: 일부 기존 파일 수정
  - 1~3: 기존 파일 덮어쓰기
  - 비고:
- 맥락 적합성: 5/10
  - 9~10: 나의 상황에 정확히 맞음 + 상황별 분기/예외까지 고려
  - 7~8: 나의 상황에 맞음
  - 4~6: 일반적인 애자일 수준
  - 1~3: 상황과 무관
  - 비고: 내용이 간소화되어 있기 때문에 사용자가 느끼는 것은 일반적인 애자일 수준 밖에 느낄 수가 없음. 그에 따라 LLM 의 랜덤성에 더 기댈 수 밖에 없는 스킬이
  만들어질 수 있겠다라는 생각이 들었음.
- 터미널 환경 자각: 1/10
  - 9~10: 터미널 환경의 제약/특성을 인지하고 결과물에 적극 반영 + 대안 제시
  - 7~8: 터미널 환경을 인지하고 결과물에 반영
  - 4~6: 부분적 인지
  - 1~3: 환경 무관하게 생성
  - 비고:
- UX 선택권 제공: 2/10
  - 9~10: 선택지 제시 + 추천 의견 + 각 선택의 결과 설명
  - 7~8: 선택지 제시 + 추천 의견 포함
  - 4~6: 선택지 또는 추천 중 하나만
  - 1~3: 일방적으로 결정
  - 비고: 사실상 Codex 처럼 선택권은 없었음.
