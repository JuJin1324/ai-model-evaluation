## 정성 소감

1. 질의를 통해 함께 만들어가기보다 결과부터 도출하려는 경향이 강함. 초창기와 크게 달라지지 않은 특성.
2. 기존에 참고할만한 레퍼런스 파일(.claude/skills/ 아래 run-eval, update-skill-reference)을 찾아서 그대로 따라 만드는 특성이 매우 강함. Codex 자체 스킬 형식(front matter 분리, allowed-tools 미지원)이 아닌 .claude/skills 형태로 생성.
3. 기존 스킬의 메타데이터("평가 용이성")까지 참고해버려 의도에서 벗어남. Codex의 레퍼런스 추종 특성이 매우 잘 드러남.
4. MVP 관점으로 하나의 스킬만 먼저 만들었다는 논리는 긍정적 — 애자일에서 MVP를 자연스럽게 추론.
5. 제안 의도는 사용자가 직접 물어보지 않으면 알려주지 않음. 경주마처럼 빨리 달릴 수 있게 목줄을 풀어달라는 느낌. 그래도 물어보면 논리적 답변을 줌.
6. 3개 스킬로 분리 후 리뷰 시, 사용자 의견이 반영되지 않고 Codex의 추론만 들어가 커스텀 스킬이라는 느낌이 약함. Claude Code Opus는 사용자 의견 반영 느낌, Codex는 "따르라"는 느낌.
7. **비격리 환경에서의 레퍼런스 흡수 특성:** Opus 평가 직후 비격리 환경에서 Codex로 스킬 생성 시, 이미 존재하던 Claude 스킬들(`.claude/skills/`)을 자동으로 참조해 동일하게 생성함. 처음에는 성능이 월등한 것처럼 보일 정도로 매끄러웠으나, 실제로는 Claude 스킬을 그대로 흡수한 것. "바퀴를 새로 만들지 마라"는 원칙이 코어 레벨에서 매우 깊이 내재된 것으로 보임. Codex 레퍼런스 문서에서도 확인: 스킬이 항상 참조 문서를 먼저 찾는 방식으로 설계되어 있음.
8. **코드 컨벤션 일관성에 강점:** 레퍼런스 추종 특성의 실용적 함의 — 기존 코드베이스에 일관된 컨벤션으로 코드를 추가하는 작업(대규모 코드베이스 편입, 스타일 일관화 등)에서 Codex가 가장 뛰어날 것으로 추측됨. 참조할 패턴이 많을수록 오히려 성능이 올라가는 구조로, "레거시가 많은 환경"에서 역설적으로 강점이 됨.
