## 3. 모델별 특징

### Claude Code Opus 4.6 — "함께 만드는 파트너" (53/80)

**강점:**
- 사용자와의 협업 프로세스가 압도적으로 우수 (상황 파악 9, UX 선택권 8)
- 전략적 질문 → 확인 → 실행의 흐름이 자연스러움
- 선택지에 추천 prefix를 붙여 사용자의 판단을 보조
- MVP 완료 후 다음 스킬로 연결하는 가이드 제공

**약점:**
- 터미널 환경에서 질문 과부하: 너무 많은 질문을 한꺼번에 쏟아냄
- 기존 작업물 참고 성향이 약함 — 자체 추론 위주
- mermaid 대신 ASCII 다이어그램 추천 (터미널 환경 자각 1점)

**핵심 특성:** AI가 인간의 개입을 이끌어내는 스타일. 사용자가 적극적으로 참여하지 않아도 AI가 질문과 선택지를 통해 참여를 유도함.

---

### Claude Code Sonnet 4.6 — "효율적인 실행자" (44/80)

**강점:**
- 결과물 품질이 Opus에 필적하거나 상회 (제안 독창성 8, 맥락 적합성 9)
- Argument 기반 워크플로우 분기라는 참신한 설계
- Mermaid 다이어그램으로 스킬 흐름 시각화
- 스킬 간 결합도 방지를 위한 파일명 참조 설계

**약점:**
- 초반 질문 후 후속 질문 없이 진행 (상황 파악 4)
- 사용자에게 제안하는 것이 거의 없음 — 내가 먼저 요청해야 함 (UX 선택권 3)
- 터미널 환경 자각 부족 (1점)

**핵심 특성:** 모호한 부분만 질문하고 나머지는 자체 추론으로 보조. "정보 부족으로 어쩔 수 없이 진행한 추론"이 아닌 "사용자가 생각치 못한 부분을 보조해주는 추론"이라는 느낌. Opus가 아님에도 높은 결과물 품질.

---

### Gemini CLI 3 Pro/Flash — "체계적 인프라, 얕은 깊이" (31/80)

**강점:**
- 스킬 관리 인프라(Skill Creator/검증/설치)가 4모델 중 가장 성숙
- .gemini/skills/ 별도 설치로 기존 프로젝트 오염 자연 방지
- 스킬 통합에 대한 논거(맥락 유지, 트리거 충돌 방지, 철학적 연속성)가 매우 설득력 있었음

**약점:**
- SKILL.md 내용이 매우 축약되고 보편적 — 철학을 제대로 담지 못함
- 사용자와의 협업 프로세스가 약함 (상황 파악 2, 설계 논의 2)
- 영어로 답변하는 경우가 자주 관찰됨
- 터미널 환경 자각 부족 (1점)

**핵심 특성:** "설명을 걷어내고 행동 지침만 남겼다"는 독자적 철학. LLM 내부 지식과의 시너지를 어필하지만, 실제 스킬 실행 없이는 검증 불가. 인프라는 좋으나 내용의 깊이가 부족.

---

### Codex CLI GPT-5.3 — "빠른 레퍼런스 추종자" (28/80)

**강점:**
- 기존 패턴 참고 능력이 4모델 중 최고 (9점)
- 기존 프로젝트 작업물과의 일관성을 암시적으로 맞추려는 특성
- MVP 관점을 애자일에서 자연스럽게 추론하여 "MVP"를 명시적으로 언급
- 물어보면 의도에 대한 논리가 높은 답변 제공

**약점:**
- 질문 없이 결과부터 도출 (상황 파악 1, 설계 논의 1)
- 사용자 의견이 반영되지 않고 자체 추론만 반영 (UX 선택권 1)
- 레퍼런스 추종이 너무 강해 원치 않는 메타데이터까지 포함
- Codex 자체 스킬 형식이 아닌 .claude/skills 형태로 생성

**핵심 특성:** "결과 먼저, 논의 나중" 스타일. 경주마처럼 빨리 달리려는 성향. 기존 작업물을 잘 참고하지만, 그로 인해 독창성이 떨어지고 사용자 커스텀 느낌이 약함.

## 4. 핵심 발견

### 가장 큰 차별점: "인간 개입 유도력"

이번 평가에서 가장 크게 느낀 차이는 **프로세스에서 인간의 개입을 AI가 이끌어내느냐** vs **사용자가 주도해야 하느냐**의 차이였음.

- **AI가 이끌어내는 모델:** Claude Code Opus 4.6 — 질문과 선택지를 통해 사용자 참여를 자연스럽게 유도
- **사용자가 주도해야 하는 모델:** Sonnet, Codex, Gemini — 사용자가 먼저 제안하거나 요청해야 원하는 방향으로 진행

### 공통 약점: 터미널 환경 자각

4모델 모두 터미널 환경 자각에서 1점. CLI 에이전트임에도 터미널 환경의 제약과 특성을 결과물에 반영하지 못하는 것은 공통적인 한계.

### 문서 안전성은 모두 양호

4모델 모두 기존 파일을 수정하지 않고 새 파일만 생성 (7점). 이 부분에서는 차이가 없음.

## 5. 상황별 모델 추천

### "내가 뭘 원하는지 아직 모호할 때" → Claude Code Opus 4.6

- 전략적 질문을 통해 사용자의 의도를 함께 정리해줌
- 선택지를 제시하며 사용자의 생각을 구체화하는 데 도움
- 설계 과정에서 함께 고민하는 느낌이 필요할 때 적합

### "내가 원하는 방향이 명확하고 빠른 결과물이 필요할 때" → Claude Code Sonnet 4.6

- 최소한의 질문 후 높은 품질의 결과물을 빠르게 생성
- Argument 기반 유연한 설계, Mermaid 시각화 등 결과물의 완성도가 높음
- 비용 효율적이면서도 Opus에 필적하는 결과물 품질
- 단, 사용자가 방향을 적극적으로 제시해야 함

### "기존 프로젝트의 패턴과 일관성이 중요할 때" → Codex CLI GPT-5.3

- 프로젝트 내 기존 작업물을 가장 잘 참고하여 일관된 결과물 생성
- 레퍼런스가 풍부한 프로젝트에서 기존 패턴을 따라야 할 때 유리
- 단, 사용자 의견 반영이 약하므로 결과물 리뷰에 시간을 투자해야 함

### "스킬 관리 체계가 중요할 때" → Gemini CLI 3 Pro/Flash

- Skill Creator/검증/설치라는 체계적 인프라가 필요한 환경에 적합
- .gemini/skills/ 별도 관리로 프로젝트 오염 방지가 자연스러움
- 단, 생성되는 스킬 내용의 깊이가 얕으므로 반복적 개선이 필요
- 한국어 지원 안정성에 주의

## 6. 유의사항

- **단건 평가**: 각 모델당 1회 평가이며, LLM 특유의 응답 랜덤성으로 결과물 품질은 매번 달라질 수 있음
- **스킬 미실행**: 생성된 스킬을 실제로 실행해보지 않았으므로, 스킬 자체의 실용성 평가는 포함되지 않음
- **코딩이 아닌 워크플로우 평가**: 이 평가는 코딩 능력이 아닌 2W1H 워크플로우 이해와 설계 능력을 측정한 것
- **평가 프레임워크 자체의 한계**: 터미널 환경 자각 항목에서 4모델 모두 1점인 것은 평가 기준 자체의 재검토가 필요할 수 있음
