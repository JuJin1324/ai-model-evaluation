## Q5: "내 워크플로우"의 구체적 범위
**Q: 평가 기준이 되는 "내 워크플로우"가 정확히 무엇인가요?**

- 이 저장소의 **2W1H 브레인스토밍** 워크플로우?
- 일반적인 **코딩 작업** (리팩토링, 버그 수정, 기능 추가)?
- **문서 작성/정리** 작업?
- 위 전부를 포함하는 종합적인 워크플로우?

**답변:**
```
일반적인 코딩 작업은 딱히 차별화가 없는거 같아. 생각보다 AI 시대에 이제는 크게 중요하지 않을만큼의 상향 평준화가 되었다고 생각해.
그보다 이 저장소에 있는 워크플로우를 얼마나 잘 실행할 수 있느냐인거 같아.
이 워크플로우에는 문서 작성 및 업데이트와 같은 작업들도 함께 포함되어있어.
```

## Q6: "AI에게 바란다" 평가 기준의 범위
**Q: 현재 `must-ai-do-things.md`에 있는 4개 항목만으로 평가할 건가요, 아니면 평가 프레임워크를 만들면서 항목을 확장할 건가요?**

현재 항목:
1. 파일 수정 시 덮어쓰지 말 것 (부분 수정)
2. 지식의 저주 주의 (문맥 없는 독자 고려)
3. 해피 패스만 말고 엣지 케이스 커버
4. 도메인과 동떨어진 예시 지양

**답변:**
```
AI 에게 바란다 부분과 함께 평가하고 싶은 항목들은 다음과 같아.

1.문서 수정 요청시 기존의 내용을 덮어쓰지 않아야함. 
2.머메이드와 같이 시각화 다이어그램을 잘 만들어줘야함. 
3.설계 시각화 제안을 어떻게 하는지 봄. 
4.이행 이전에 과정을 브리핑하고 확인을 받고 하는가?
5.스킬 이행률 검증
6.대한민국 백엔드 개발자 채용에 관해서 나에게 맞는 일자리 찾아주는 것과 같이 리서치 능력 평가
```

## Q7: "당일 평가"의 의미 확인
**Q: 신규 모델 나온 당일에 평가한다는 건, 아래 이해가 맞나요?**

- 평가 태스크(테스트 케이스)가 **미리 준비**되어 있어야 함
- 자동화 스크립트가 **바로 실행 가능**해야 함
- 수동 체크리스트도 **미리 확정**되어 있어야 함

→ 즉, 이 프로젝트의 산출물은 "평가 결과"가 아니라 **"반복 실행 가능한 평가 프레임워크"**인가요?

**답변:**
```
이 프로젝트의 산출물은 일단 반복 실행 가능한 평가 프레임워크가 맞아. 다만 각 모델의 성장 과정을 추적할 수 있도록 평가 결과 역시도 있는게 좋을거 같아.
```

## Q8: "비용 계산"의 범위
**Q: 비용 계산이란 구체적으로 무엇을 비교하려는 건가요?**

- API 토큰 비용 (input/output 토큰당 가격)?
- 구독 비용 (월정액)?
- **같은 태스크를 수행했을 때의 비용 대비 품질** 비교?

**답변:**
```
토큰 비용과 함께 구독 비용에 대한 평가가 함께 필요할거 같아. 품질 테스트는 이미 위에서 정의했으니까 말이야.
```
